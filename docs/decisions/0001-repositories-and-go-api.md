# 0001: два репозитория и Go public API

- **Статус:** принято как начальная архитектурная граница.
- **Дата:** 2026-10-28.

## Решение

Продукт использует два репозитория: Android-клиент `passport-android` и backend `passport-backend`. В одном backend-репозитории находятся два компонента: публичный Go API и внутренний Python runtime PaddleOCR. Только Go API принимает внешний HTTP трафик; Python доступен только Go через внутренний интерфейс. Компоненты могут быть упакованы в отдельные контейнеры после проверки совместимости целевого компьютера; контейнеры не обязательны для локального запуска.

## Причины

Go владеет публичным контрактом, доступом, проверками, orchestration, валидацией и JSON. Python нужен как изолированный runtime OCR; он не представляется публичным API или native Go моделью. При контейнерной упаковке отдельные контейнеры позволяют ограничивать внутренний inference и независимо описывать его зависимости, сохраняя один репозиторий backend.

## Последствия и статус

OpenAPI черновик в [`api/openapi.yaml`](../../api/openapi.yaml) описывает внешний Go API. Он не гарантирует, что сервер уже реализован или доступен. Продуктовое требование — доступ к Go API через стабильный HTTPS endpoint из любой сети с интернетом; способ публикации, домен, модели, версии, лимиты и авторизация остаются открытыми до пилота и выбора размещения.
