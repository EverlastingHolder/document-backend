# Шаблонные поля после выравнивания

Дата: 2026-10-29. Статус: `EXPERIMENTAL_FRESH_PAIRED_RUN_COMPLETED`.

## Маршрут

`template_field_pipeline.build_template_passport` выполняет физическую регистрацию до OCR, сохраняет две выровненные страницы в отдельное canonical изображение, читает страницы и уточняет области шести полей: фамилия, имя, отчество, пол, место рождения, орган выдачи. Модели — прежние pinned PP-OCRv5 mobile/eslav через RapidOCR. Даты, код подразделения, серия и номер продолжают извлекаться существующим Go-парсером.

Шаблон `ru-internal-spread-anchored/v1` задаёт широкие относительные области, а не координаты конкретного снимка. Границы уточняются по наблюдаемым строкам ФИО, датам на разных страницах, коду подразделения и обнаруженной MRZ-границе. Эталон не принимается планировщиком или OCR-функциями.

Для включения шаблона необходимы contour-регистрация, совпадение ID/SHA/размеров canonical raster и lineage, сгиб, одна подходящая календарно допустимая дата на каждой странице и три упорядоченные выровненные строки ФИО перед датой рождения. Это структурная поддержка вертикальной ориентации и layout, не проверка подлинности документа. При недостающих/неоднозначных опорах шаблон отключается; его координаты не переносятся на исходное фото при fallback.

ФИО и пол читаются полосами `rec_only`. Многострочные поля сначала проходят detector+recognizer; соседние наблюдаемые строки дополнительно читаются по полной ширине поля. Тесные word boxes могут пропускать короткий префикс, поэтому они не задают горизонтальные границы повторного чтения. Оба чтения сохраняются как отдельные гипотезы. Число строк ограничено; далёкие строки и разные колонки не склеиваются.

## Координаты и предложения Go

Canonical PNG имеет собственные ID, SHA и размер. Его `exif_normalized_pixels` относятся к этому изображению; исходное фото имеет отдельную идентичность. Piecewise lineage связывает каждую панель с исходным фото. Для `rec_only` геометрия означает весь crop, не границы символов; для detector mode сохраняются фактические bbox.

Private handoff — [template-evidence-v1.schema.json](../ocr/schema/template-evidence-v1.schema.json). Go CLI принимает его через `--template-evidence`. Без этого аргумента поведение CLI сохраняется. `ApplyTemplateEvidence` проверяет изображение, происхождение регистрации, опоры, границы, режимы и формат записей. Crop-текст не выдаётся за строку исходного OCR pass; provenance хранится в `Candidate.template_evidence`. Публичный API не меняется.

Для русских текстовых полей допускается предложение замены только известных визуально одинаковых заглавных Latin/Cyrillic символов. Это не транслитерация и не исправление написания по словарю. Raw текст, score, режим, crop, опоры и модель сохраняются; неизвестная латиница не угадывается.

Равные значения объединяют provenance. Разные остаются отдельными кандидатами: `value=null`, `state=uncertain`. OCR score не выбирает победителя; повторное согласие с одним из конфликтующих кандидатов не снимает конфликт. Эталон читает только оценщик после всех Go-результатов.

## Фактический пилот

Выполнен свежий маршрут registration → page OCR → template crops → Go на двух development-фото. Исходный OCR baseline взят из неизменённого сохранённого среза с теми же pinned моделями и заново обработан текущим Go. Registration-only arm распознан заново. Во всех arms: `--passes=all --normalize-names=true --mrz-policy=augment`.

| Режим | Правильные выбранные предложения | Неверные выбранные предложения | Пропуск / конфликт | Правильный вариант есть среди кандидатов |
|---|---:|---:|---:|---:|
| Исходный OCR + Go | 15 | 3 | 2 | 15 |
| Выравнивание + OCR страниц + Go | 15 | 3 | 2 | 15 |
| Дополнение чтением областей | 15 | 2 | 3 | 16 |

Всего 20 обязательных полей. Последний столбец не означает 16 автоматически заполненных полей: правильное место рождения теперь доступно среди кандидатов, но конфликтует с предыдущим чтением. Вместо неверного предложения поле оставлено для ручного выбора. Прежние 15 правильных выбранных предложений сохранены. Отчество отдельно остаётся конфликтным; оно не входит в 20 обязательных полей.

Шаблон активирован на первом снимке. На втором регистрация неоднозначна и работает исходный маршрут. Все предложения требуют проверки человеком. Два снимка использовались при разработке: это не holdout и не подтверждение стабильности на новых фото.

## Исправление режима и проверки

RapidOCR сохраняет `use_det` между вызовами. После `rec_only` общий экземпляр мог обработать следующую страницу без детектора. В `region_pipeline` и `registration_first_pipeline` полностраничные вызовы теперь явно задают `use_det=True, use_rec=True, use_cls=False`; поля явно задают свой режим. Добавлены проверки переключения полосы/страницы и lazy provider validation. Свежий прогон подтвердил восстановление исходного fallback-результата.

`run_template_field_comparison.py --fresh` принимает два исходных файла, cache-root исходного baseline, work-root, output-dir и private gold. Без `--fresh` проверяется чтение полей на сохранённых зарегистрированных страницах. Reusable функция `build_template_passport` возвращает observations и необязательный template evidence sidecar для Go. Полный локальный прогон ограничен таймаутом.

Прошли `go test ./...`, 60 связанных Python-тестов без моделей, компиляция Python, gofmt и свежий парный OCR-прогон. Проверены неизменность исходников/входов, привязка изображений, фактические CPU sessions и отсутствие raw текста, эталонных значений, source paths/hashes в публичном отчёте. SHA, команды, exit codes и логи сохранены в приватном verification ledger.

## Исправление геометрии crop

29 октября 2026 в новом sample был найден сбой Go-валидации: паддинговые crop имени пересекали соседние опоры или достигали строки даты рождения. Исправлен producer: целочисленные ROI теперь сохраняют полную опору имени, проходят после шва, заканчиваются строго до даты рождения и не перекрывают соседние строки. Невыполнимый ROI пропускается с приватной причиной; Go-контракт не ослаблялся. Добавлены синтетические проверки плотных строк, дробных координат, границы даты и пропуска невыполнимого поля. Свежий полный пятикадровый прогон ещё ожидает выполнения; результаты точности не обновлялись.
