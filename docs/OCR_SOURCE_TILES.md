# Source-tile OCR: ограниченный эксперимент

> Исторический эксперимент. Go evaluator и observations/extraction pipeline удалены; команды из прежних запусков больше не доступны.

**Статус: эксперимент завершён; source-tile маршрут остаётся выключенным по умолчанию и не подключён к production/API. Прироста точных предложений не получено.** Результат ниже относится только к пяти development-фото и не оценивает общую точность OCR.

## Что проверялось

В [source-tile pipeline](../ocr/experiments/source_tile_pipeline.py) добавлен opt-in путь для изображений, где регистрация разворота не дала template observations: исходное изображение делится на ограниченное число тайлов, OCR-строки добавляются как дополнительные observations, а Go extractor запускается над результатом. Этот маршрут не меняет публичный API, не принимает эталон и не выбирает значения по эталону. Его можно отдельно проверять и развивать; текущие default passes и production wiring не переключены.

Новый тип pass `source_tile` передаётся внутри схемы [observations v3](../ocr/schema/observations-v3.schema.json). В [Go-контракте observations](../internal/passport/observations.go) этот тип разрешён только в v3, ограничен шестью проходами и проверяется на допустимую геометрию. Координаты остаются в пикселях исходного изображения после EXIF-нормализации. Это внутренний Python-to-Go handoff, не схема публичного ответа.

## Метод и ограничения

Сравнивались сохранённые результаты baseline и source-tile маршрута для 10 обязательных полей на каждом из пяти development-фото. Source-tile выполнялся на трёх фото с fallback-маршрутом; два других повторно использовали проверенный baseline. Один набор содержит повтор уже встречавшегося документа, а два фото относятся к другим документам без MRZ, поэтому эти пять фото не являются независимой held-out-выборкой.

`correct / wrong / abstain` оценивает только выбранное значение против эталонного значения. Классификация не зависит от `recognized` или `uncertain`: uncertain-значение может совпасть или не совпасть с эталоном, но всё равно требует ручной проверки. Флаги ручной проверки пересекаются с тремя исходами и считаются отдельно. Наличие правильного кандидата — отдельная метрика; оно не превращает его в выбранное значение и не форсирует выбор.

## Результат

| Фото | Baseline C/W/A | Source tiles C/W/A | Ручная проверка до→после | Правильный кандидат до→после |
|---|---:|---:|---:|---:|
| sample-01 | 9/0/1 | 9/0/1 | 10→10 | 10→10 |
| sample-02 | 6/2/2 | 6/1/3 | 8→8 | 6→6 |
| sample-03 | 4/2/4 | 4/2/4 | 7→7 | 5→5 |
| sample-04 | 2/1/7 | 1/1/8 | 4→4 | 3→3 |
| sample-05 | 6/4/0 | 6/2/2 | 9→10 | 6→6 |
| **Итого** | **27/9/14** | **26/6/18** | **38→39** | **30→30** |

Правильных выбранных значений стало на одно меньше; три неверных выбора перешли в abstain, и ещё один прежде правильный выбор стал abstain. Доступность правильного кандидата не изменилась. Для необязательного отчества обе ветки дали 0 correct / 0 wrong / 5 abstain; флаги ручной проверки — 5→5, правильный кандидат доступен в 4→4 случаях.

В этом сравнении дополнительные OCR-строки не создали новых правильных кандидатов и не улучшили число правильных выбранных полей. Они также не привели к увеличению неверных выбранных значений: часть прежних ошибок стала abstain. Это указывает на возможную следующую задачу в локализации строк, меток и областей полей до сборки кандидатов; результат не доказывает общего недостатка используемой OCR-модели.

## Проверки и границы вывода

Для кода подтверждены 72 Python-теста и `go test` для пакетов `internal/passport`, `internal/mrz` и `cmd/ocr-eval`. Сравнение завершилось на пяти фото после проверки parity и целостности артефактов; все 14 tile-проходов в этом запуске завершились со статусом `ok`. Эти проверки подтверждают исполнение и контракт, но не качество на новых документах или готовность к production.

Данные не обосновывают включение source-tile маршрута по умолчанию, изменение production route или утверждение о качестве на других изображениях. Для решения о дальнейшем развитии нужны независимые документы, заранее заданные правила выбора и review, а также отдельная оценка localization/ROI-гипотезы. До такой проверки результаты остаются экспериментальными, все значения требуют подтверждения человеком.

Отдельная raw-reader диагностика по вручную выбранным областям полей описана в [диагностике field ROI](OCR_ROI_DIAGNOSTIC.md). Она не меняет результаты source-tile сравнения и также не подтверждает production-качество.
