# Offline serial ROI preview contract

> Исторический preview. Go command, locator и Python runner удалены; эту схему больше нельзя выполнить из текущего backend.

Status: experimental preview contract, version `passport-serial-roi-preview/v1`. This is a standalone geometry proposal format. It does not change the public API, the active VL v1 plan, reader selection, inference, or field assembly.

## Runner

`go run ./cmd/serial-roi-preview -input request.json [-output proposal.json]` reads one JSON request containing an explicit raster frame and saved `passport-ocr-observations/v1..v3`. It performs no OCR, model loading, network access, or source image decoding. Raster ID, dimensions, and SHA-256 must match the observations image metadata. Output files are created with mode `0600`.

```json
{
  "raster": {"id":"canonical-raster-id","width":1200,"height":800,"sha256":"<64 lowercase hex characters>"},
  "observations": {"schema_version":"passport-ocr-observations/v3","image":{},"document":{},"passes":[],"lines":[]},
  "page_frame_kind":"registered_pages",
  "pages": [{"id":"page-a","bounds":[0,0,1200,800]}]
}
```

The example is schematic: observations must satisfy the existing observations validator. `page_frame_kind` is required. `registered_pages` requires nonempty `pages` taken from validated canonical registration lineage. `whole_document_fallback` forbids `pages`; Go uses the saved document bounds and ignores OCR seam/pass crops as physical page boundaries. Explicit page bounds must be raster-frame coordinates. A page may include `source_to_raster` only with `transform_provenance_id`; upper/lower page transforms must be passed separately. The raster must be the coordinate frame represented by those observations; do not pass a different source photo while claiming the same frame.

## Output

The versioned result binds every proposed quad/bounds to `raster.id`. It carries an overall status/reason, `orientation_unverified`, rotation hypotheses, relative geometry support, a shared-column proposal, separate series and number proposals, and per-ROI optional source transform plus provenance ID. Source mapping is emitted only when the supplied matrix is finite, nonsingular, has source frame ID/dimensions/hash and source page corners, and maps those corners into the declared raster page bounds. `transform_validation` is explicitly `mathematically_validated_pixel_unverified`: this is only a mathematical and metadata check. The Python renderer must separately verify source/raster hashes and corner correspondence against its loaded artifacts before treating the chain as pixel-proven. A provenance string alone is not proof. A spread's upper and lower pages require separate transforms; no global spread transform or implicit identity is valid.

Allowed statuses are `proposed`, `ambiguous`, and `insufficient_geometry`; ROI status may be `proposed`, `ambiguous`, or `unavailable`. Sorting uses exact scores with stable geometry tie-breaks; ambiguity tolerance is evaluated separately against the exact maximum score. When column/page scores are tied within tolerance, output status and selected ROIs are `ambiguous`, the display hypothesis is deterministic, and alternatives are included for review. The renderer must label every ambiguous box as ambiguous, never resolved. Missing/ambiguous geometry must not be filled with hand-entered boxes or expected field values. The locator may use saved OCR token patterns and their geometry, but output does not echo OCR text or values. Pattern-category metadata identifies shapes such as `four_digit_run`, `six_digit_run`, `ten_digit_run`, `two_plus_two_digit_runs`, `two_plus_two_plus_six_digit_runs`, `two_plus_two_plus_four_digit_runs`, `geometry_only_sibling`, `composite_sibling_boundary`, or `bounded_geometry_search`. For composite OCR lines, a separate six-digit source quad that overlaps the composite and matches its reading axis provides the number ROI and the series boundary; the resulting prefix ROI carries `composite_sibling_boundary_manual_review`. Without such a sibling, a 10-digit observation is divided into 4/6 spans along the source quad reading axis; those ROIs carry `proportional_character_span_manual_review` and require visual review because glyph boundaries are not available. A `two_plus_two_plus_four_digit_runs` observation supports only provisional series-prefix geometry and never supplies a complete number. If no series pattern is recognized, short same-page neighboring quads with parallel axes and relative size near the four/six digit ratio may support a `geometry_only_sibling_manual_review` proposal. When no sibling quad qualifies, the output may include a bounded `bounded_geometry_search_manual_review` region placed before the number anchor in the same page and column. These are uncertain geometry proposals for manual/ink-geometry review; none claims field recognition. A series ROI is never copied from the number ROI. Every proposed ROI has `manual_review_required: true`; geometry does not claim successful field reading.

The Go entrypoint clusters right-side numeric token boxes by relative geometry, preserves overlapping candidates with different structural roles, excludes only lines whose originating pass is MRZ, and proposes boxes only when there is a supported numeric column. A standalone six-digit source quad paired with nearby series geometry takes precedence over a proportional composite span. Short geometry-only candidates are grouped when adjacent, including small AABB overlaps when the boxes are not near-duplicates. Two-group spans may extend to 1.15 times the number-axis length to allow inter-group spacing; a single short group anchors a bounded estimate of `4/6 * number-axis length + 0.75 * glyph cross-size`, expanded away from the number. Existing observed series spans are preserved when longer than this font-based estimate. The cross-axis context extends by at most half a glyph cross-size per side and is clipped to the page. For an unanchored bounded series search, an additional 0.35 of the planned span extends only the far-from-number edge; the near-number edge remains fixed and the result is clipped to the same page. This is search context for manual review, not a tight ink boundary. These estimates use the `estimated_manual_review` reason and remain manual-review-only. Sibling search works on either side of a number anchor. For singleton-token support, the registered-page threshold is 10% of page height; whole-document fallback uses 5% because its frame contains approximately two page heights, preserving the same minimum pixel scale. Document-wide fallback pairs by local geometry and does not treat saved OCR seams or pass crops as physical pages. These are development heuristics, not a validated template classifier. Quarter-turn helper input uses finite integer coordinates for half-open pixel-edge crop bounds. Quarter-turn and homography helpers are pure geometry utilities; they do not assert semantic orientation. This schema remains preview-only and does not activate ROI inference.
