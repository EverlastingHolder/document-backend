# Внутренний OCR runtime

Go остаётся единственным владельцем публичного API, состояния jobs и канонического `RecognitionResponse`. Синхронный provider продолжает работать как приватный дочерний процесс с JSON stdin/stdout. Для очереди используется отдельный Python consumer с resident RussianDocsOCR pipeline; у него нет публичного порта и credentials к PostgreSQL.

## Async consumer

`runtime/async_consumer.py` получает только идентификаторы из durable quorum queue `passport.recognition.work`. Envelope имеет фиксированную форму `{schema_version:1,event_id,job_id,attempt_no}`; сообщение и DLQ не содержат изображение, путь, владельца или OCR поля. Consumer объявляет direct exchange `passport.jobs`, routing key `recognition.requested`, `single-active-consumer`, `prefetch=1`, manual ACK и DLX `passport.jobs.dlx` с диагностической очередью `passport.recognition.dead`. Настройки объявления очередей должны совпадать с Go publisher.

Перед запуском consumer загружает и прогревает модель, затем публикует subscription. При работе отдельный поток делает claim/RPC и OCR; Pika connection thread остаётся свободен для heartbeat. Все ACK и закрытие канала выполняются через `BlockingConnection.add_callback_threadsafe` на I/O thread. Worker ACK-ит только после ответа Go `decision=ack`, когда Go подтвердил terminal result или durable retry. При неопределённом RPC результате сообщение остаётся unacked, канал закрывается для повторной доставки. Ответ `wait` удерживает delivery и повторяет claim с задержкой, без немедленного nack/requeue цикла.

Go claim сообщает attempt token, UUID image key, media type, size, `hard_processing_timeout_ms`, `completion_budget_ms`, deadline, lease и pipeline version. Consumer открывает только `<image_root>/<image_key>` с UUIDv4-именем, сверяет размер с БД, а OCR child проверяет формат, MIME, пиксели и ограниченный размер. Python передаёт Go только исходные 11 extraction fields. Go применяет прежний canonical mapper, сохраняет результат/метрики и решает retry; Python не формирует публичный результат.

OCR выполняется в отдельном killable child с resident model. Если hard deadline истёк, supervisor завершает process group, убивает процесс после bounded grace и прогревает новый до следующей задачи. На Linux worker child устанавливает `PR_SET_PDEATHSIG`, поэтому аварийное завершение consumer не оставляет orphan model process. При потере Rabbit connection consumer ждёт завершения или остановки текущей попытки перед reconnect, чтобы не запускать параллельный OCR.

## Контейнер и приватные артефакты

`deploy/Dockerfile.ocr` устанавливает закреплённые Python dependencies и копирует только runtime wrapper, consumer, secret bootstrap и entrypoint. Dockerfile-specific `.dockerignore` исключает остальной repository, `.git`, local outputs, environments, RussianDocsOCR checkout и веса. Контейнер начинает root только для bootstrap: он принимает password/token только из двух смонтированных secret targets, копирует их вместе с read-only config в отдельный tmpfs `/run/passport-ocr`, устанавливает владельца и mode `0600`, затем сбрасывает supplementary groups/GID/UID до `PASSPORT_WORKER_UID`/`PASSPORT_WORKER_GID` (по умолчанию `10001`) и exec-ит consumer. Другие operator paths bootstrap не копирует; исходные config/secret mounts не изменяются. Compose должен монтировать тот же API image root `/var/lib/passport/images` read-only, сохранить выбранный на этапе intake root без копирования/chown и задать UID/GID, совпадающие с API. `work_root` — отдельный writable scratch path; source checkout и models mount read-only.

Worker JSON config находится по умолчанию в `/run/config/ocr-worker.json` (путь можно задать `PASSPORT_OCR_CONFIG_FILE`). В нём задаются Rabbit host/user/vhost и путь password file, Go worker base URL и путь raw worker token file, topology, private image/source/model/work roots, upload/image limits, обязательные `expected_upstream_version` и `expected_model_lock_version` из выбранного read-only snapshot, а также timeout settings. Consumer не подменяет выбранный clone или модели и не загружает новые версии. Go top-level `pipeline_version` остаётся единственным источником версии pipeline и приходит в Claim; отдельное значение pipeline version в Python config не задаётся. Секреты не вставляются в JSON: пароль Rabbit и raw `pwt1_` token читаются из отдельных private files с mode `0600` или строже, затем временно хранятся в приватном tmpfs после privilege drop. Worker token проверяется server-side Go hash-only registry; его нельзя помещать в Rabbit message, environment, command line или logs. Private Go URL используется только во внутренней Compose сети и не следует redirect.

Queue consumer timeout `consumer_ack_timeout_ms` должен совпадать с Go queue configuration. Go claim задаёт processing deadline и completion budget; `http_timeout_ms` не должен превышать completion budget. Перед OCR worker проверяет, что оставшийся lease и budget укладываются в broker ACK timeout. Значение таймаута задаёт оператор; consumer не назначает deadline/SLA. RabbitMQ рекомендует для consumer acknowledgement timeout не опускаться ниже пяти минут; это broker guidance, не продуктовый срок завершения задачи.

При старте consumer сверяет `expected_upstream_version` с `document_processing.__version__` и `expected_model_lock_version` с `models.lock.json` внутри выбранного source snapshot, затем сверяет размер и SHA-256 каждого файла модели с этим lock manifest. Значения обязательны; автоматического выбора «latest» нет. Оператор должен смонтировать тот же source/model snapshot, который использует существующий OCR runtime. Этот lock-проверочный шаг не подтверждает, что snapshot является историческим baseline данного проекта; checkout и lock manifest должны оставаться из одной приватной комплектации. Не добавляйте checkout, weights, реальные паспортные изображения, приватные OCR выводы, model caches или виртуальные окружения в Git и Docker build context.

## Зависимости и проверки

`requirements-worker.txt` закрепляет Pika и CPU inference dependencies по compatibility profile upstream RussianDocsOCR `4.6.0`; этот выбор не доказывает совместимость с текущим проектным clone или weights. Upstream `4.6.0` поддерживает Python 3.10–3.12; контейнерный base использует Python 3.12.16. Если выбранный существующий snapshot требует другие зависимости, профиль нужно пересмотреть и принять на реальном OCR runtime; consumer не обновляет source/models автоматически. Linux model assets не включены в этот репозиторий и не устанавливаются из скрытой локальной среды.

Unit/orchestrator проверки без приватных assets и broker:

```sh
python3 -m unittest ocr.runtime.test_russiandocs_worker ocr.runtime.test_async_consumer -v
```

Эти проверки покрывают strict envelope, claims, durable decision sequencing, Pika thread-bound ACK dispatch, topology declarations, timeouts и lifecycle fake child. На macOS Linux-only test `PR_SET_PDEATHSIG` пропускается; его нужно запускать в Linux container. Unit suite не проверяет Rabbit/PostgreSQL integration, реальные weights, OCR throughput, результаты на настоящих изображениях, Compose permission wiring или production readiness.

Legacy sync subprocess остаётся отдельным runtime path. Он использует тот же адаптер extraction полей, но не подключён к RabbitMQ. Детали существующей конфигурации и процесса см. в [OCR API runtime](../docs/OCR_API_RUNTIME.md); async job contract описан в [плане перехода](../docs/ASYNC_MIGRATION_PLAN.md).
